# Gunyah PAC trap — 2026-11-07

Image: `boot-v4-win2g.img`, sha256
`541dea281f8ff06287b6e2dafd57dcb18e88f6c68e3ed34b06874cdfec1b8346`
(run `42408717308`, firmware `2629889`).

The 2 GiB window worked: DarwinBoot loaded the kernel and ADT, and XNU
started. The first device-side XNU output is a panic screen:

```
Undefined kernel instruction: pc=0xfffffff00ad881c0 instr=d5
...
pages=0x0000000000000000
free=0x0000000000000000
```

`0xd5` is the first byte of the AArch64 `MRS`/`MSR` encoding group. The
faulting instruction is the `MSR APIAKeyLo_EL1` (and the following key writes)
from `PAC_INIT_KEY_STATE` in `osfmk/arm64/pac_asm.h`, added by
`patches/xnu-12377/native-pac-keys.patch`.

Cause: **Gunyah runs at EL2 and sets `HCR_EL2.APK`**, so writes to the PAC key
registers from EL1 trap as undefined instructions. This is exactly the arm64e
requirement the docs warn about.

## Experiment

`patches/xnu/pac-skip-trapped-keys.patch` disables the native key-programming
block. XNU then runs with whatever key set Gunyah installed (or with PAC
disabled if it left `SCTLR_EL1.EnIA` clear).

- If `PACIA`/`AUTIA` do not trap (`HCR_EL2.API` clear), the kernel continues;
  PAC signatures are consistent within the boot even though the key set is not
  ours.
- If the next panic is on a `PACIA`/`AUTIA` (encodings starting `0xdac1…`),
  Gunyah sets `HCR_EL2.API` too and arm64e cannot run at EL1 on this boot chain
  without changing the EL2 configuration.

No other change is required for this test; the kernel remains arm64e.

## CORRECTION (same day)

The instruction was **not** PAC. The panic line wraps on the 1080-wide screen:
`instr=d5` continues as `1be228`, so the word is **`0xd51be228`** =
`msr CNTP_CTL_EL0, x8` (capstone). The PC `0xfffffff00ad881c0` is inside
`_wfe_timeout_configure`/timer setup, and the file word there is a valid
`cmp x8, x19` because the runtime text is relocated; the executed word is the
timer MSR.

Cause: `_enable_virtual_timer()` in `osfmk/arm64/machine_routines.c` enables
the virtual timer and then, "as a precaution", writes `CNTP_CTL_EL0`. Gunyah
leaves `CNTHCTL_EL2.EL1PCEN` clear, so that EL1 physical-timer write traps as
an undefined instruction. XNU itself uses the virtual timer.

Fix: `patches/xnu/timers-avoid-trapped-physical-timer.patch` stops writing the
physical timer under the hypervisor. PAC was never proven to trap.
